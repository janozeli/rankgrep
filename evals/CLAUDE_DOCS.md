# Free agents on the complete Claude Code Markdown documentation

This experiment uses the official `https://code.claude.com/docs/llms-full.txt` export unchanged, saved as `docs/claude-code.md`: 9,973,406 bytes, 126,019 lines and 228 source pages. Every unique English Markdown page in the contemporaneous official `llms.txt` index appears in the export. Hashes, retrieval time and page URLs are frozen in `claude-docs-results/corpus.json`. The full corpus stays outside git; it is not a set of excerpts chosen for the questions.

Eight authored questions cover direct lookup, vague symptoms, multiple constraints and synthesis, two each. Questions and reference-line alternatives are frozen before model calls. All five conditions get the same question, entire read-only corpus and citation request. They may compose native tools, shell commands and pipelines freely. The model is GPT-6 Astra, medium reasoning, with priority service requested; backend scheduling is not independently verified.

Conditions are free agent, original rankgrep, capabilities description, domain description, and output-fields description. Capabilities and output reuse the earlier wording. Domain names Claude Code topics explicitly, inspired by a domain-specific documentation skill, without adding a search-first requirement. This is an exposure experiment, not a new retrieval engine: only the description changes; the original skill body, including its existing guidance, remains identical. The other skill is not installed or tested. The production plugin remains unchanged.

Sessions reuse the reviewed Bubblewrap runner: fresh home and scratch, no personal plugins/skills/configuration/memories, identical native tool definitions, read-only plugin/config mounts, and actual session-catalog checks. Each augmented session gets an independent copy of a dedicated warm runtime/index cache and warms its installed launcher before timing. No session history or gold labels are mounted. Default network tools remain available. Invocation and visible structured hits are audited from native completed commands; runtime tracebacks fail the run. Each invocation has a 1,200-second timeout, without a turn or dollar cap.

The primary retrieval measure is **reference-line coverage**, not answer accuracy. Each requirement has one or more predefined supporting lines. It is covered if a valid citation contains one alternative. Responses allow at most eight ranges, each at most 40 lines, in the actual corpus file. Overlong ranges, other paths and invalid bounds get no credit. Coverage averages requirements within each question, then questions equally. An evidence line may support multiple requirements. References are not exhaustive: valid alternative passages may receive no credit. Answers are retained for inspection but not model-graded. This differs from FreshStack nugget coverage, so scores must not be compared across the two benchmarks.

This is a small diagnostic suite, written with access to the documentation, not a representative random sample. One call per question/condition and fixed shuffled order do not establish causality or a stable winner. Setup is excluded from latency; I/O contention can still affect timing. Any inspection of missed citations must be reported separately without silently changing the frozen reference labels.

Run `uv run --group eval evals/claude_docs.py --jobs 2` after authentication. It downloads the full official export if missing, refuses changed bytes, and caches only matching manifests. The workspace is `~/.cache/rankgrep-evals/claude-docs`. To regenerate the table without model calls, use `uv run --group eval evals/claude_docs.py --report`. A future official export may differ: preserve the pinned local download rather than applying these line labels to new content.

## Results and alternative-evidence audit

All 40 sessions finished without agent errors, launcher tracebacks or invalid citations. Native audits and context hashes were verified, as were the independent dependency-file inodes across all 32 augmented-session caches. Rankgrep was used and returned hits in 6/8 original sessions, 3/8 capabilities sessions, 8/8 domain sessions and 7/8 output sessions. Naming the domain had the highest observed adoption here, but eight questions without independent repeats cannot establish a reliable improvement.

The [frozen reference scores](claude-docs-results/summary.md) were 83.33% for free, original, capabilities and domain, and 89.58% for output. Inspection of every missed requirement found valid cited passages elsewhere in the export: a repeated plugin-layout warning, a troubleshooting explanation of the loader root, a manifest table explaining plugin paths, and a hooks-guide explanation of permission rules. The original references and scores remain unchanged.

The separate [post-hoc audit](claude-docs-results/audited-summary.md) adds those equivalent evidence spans, with rationales in `alternative-evidence.json`, and applies the pooled alternatives to every condition. It was author-reviewed after observing results, not blinded or preregistered. Every condition then supports all requirements in all eight questions, including the free agent. This does not establish 100% answer accuracy or a general retrieval advantage; the test has a ceiling on audited evidence coverage. No production description or engine change follows from this run.

Run `uv run --group eval evals/claude_docs_audit.py` to validate the frozen scores and reproduce the supplemental audit. The published case records retain answers, citations, original coverage, usage, elapsed time, native invocation audits and provenance hashes. The large corpus and private execution logs remain outside git.
